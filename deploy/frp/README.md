# Переезд frps на другую машину

frps — сервер обратных туннелей. К нему подключаются роутеры и держат
соединение наружу; через эти туннели мы снимаем показания, открываем панель
устройства и ходим по SSH. Наша сторона подключается к тому же frps
контейнером `frpc` в режиме visitor.

Наш код про переезд не знает ничего и знать не должен: адрес frps он берёт
из `FRP_SERVER_HOST`, а роутеры — из того, что зашито в их прошивке.
См. [`core/config.py`](../../core/config.py) и
[`worker/tasks/frpc_config.py`](../../worker/tasks/frpc_config.py).

## Главное правило

> **Старый frps не выключается, пока на нём не останется ни одного роутера.**

Канал, по которому роутер узнаёт что угодно, — это и есть его туннель
до старого frps. Выключив сервер первым, мы теряем связь со всеми, кто
не успел переехать, и вернуть их можно будет только руками у клиента дома.
Лишняя неделя работы старой машины стоит дешевле одного такого выезда.

## Сначала — что зашито в роутерах

От ответа зависит, переезд это на полчаса или на месяц.

```bash
cd /opt/router-shop && grep -E '^FRP_(SERVER_HOST|SERVER_PORT|TLS_ENABLED|DASHBOARD_URL)=' .env
```

**`FRP_SERVER_HOST` — доменное имя.** Хороший случай: роутеры ходят по имени,
и переезд это смена A-записи. По устройствам ходить не нужно, дальше по этой
инструкции.

**`FRP_SERVER_HOST` — IP-адрес.** Тогда имя, которое вы перевесите, роутерам
ничего не скажет: они продолжат стучаться на прежний адрес. Переезд в этом
случае — это заход на каждое устройство по SSH через живой туннель, правка
`serverAddr` и перезапуск frpc на нём. Делается пачками и только при живом
старом сервере; сначала заведите имя, чтобы следующий переезд был как
первый случай.

Проверьте заодно, сколько устройств и сколько на связи:

```bash
cd /opt/router-shop && docker compose exec -T postgres psql -U "${POSTGRES_USER:-router_shop}" -d "${POSTGRES_DB:-router_shop}" -tAc "select count(*) || ' всего, на связи ' || count(*) filter (where frp_online) from devices"
```

## 1. Снять то, что надо повторить

На новой машине должны совпасть **порт**, **токен** и **TLS**. Токен — самое
опасное место: опечатка в нём означает, что весь парк подключится и получит
отказ, а выглядеть это будет как «роутеры пропали».

```bash
cd /opt/router-shop && grep -E '^FRP_(SERVER_PORT|TOKEN|TLS_ENABLED|DASHBOARD_USER|DASHBOARD_PASSWORD)=' .env
```

`FRP_STCP_SECRET` сюда не входит намеренно: ключ STCP знают только роутер
и наш visitor, frps его не видит и не проверяет.

## 2. Поднять frps на новой машине

Версия — та же, что у нашего visitor'а: `0.65.0`. Конфиг в формате TOML
(frp 0.52 и новее).

`/opt/frps/frps.toml`:

```toml
bindPort = 8443

auth.method = "token"
auth.token = "<FRP_TOKEN, ровно как на старой машине>"

# Роутеры и наш visitor подключаются по TLS. `force` запрещает открытый
# транспорт: без него случайно перенастроенный роутер подключился бы
# в открытую и мы бы об этом не узнали.
transport.tls.force = true

webServer.addr = "0.0.0.0"
webServer.port = 7500
webServer.user = "<FRP_DASHBOARD_USER>"
webServer.password = "<FRP_DASHBOARD_PASSWORD>"

log.to = "console"
log.level = "info"
```

`/opt/frps/docker-compose.yml`:

```yaml
services:
  frps:
    image: snowdreamtech/frps:0.65.0
    restart: unless-stopped
    ports:
      - "8443:8443"
      - "7500:7500"
    volumes:
      - ./frps.toml:/etc/frp/frps.toml:ro
    logging:
      driver: json-file
      options: {max-size: "20m", max-file: "5"}
```

```bash
cd /opt/frps && docker compose up -d && docker compose logs --tail=20 frps
```

## 3. Закрыть дашборд

`8443` открыт всему интернету — роутеры приходят откуда угодно. А `7500` —
это список всего парка с именами прокси, и наружу ему нельзя. Открывайте
его только адресу машины с нашим API:

```bash
ufw allow 8443/tcp comment 'frps: роутеры'; ufw allow from <IP машины с API> to any port 7500 proto tcp comment 'frps dashboard'; ufw status numbered
```

Проверка снаружи: `8443` отвечает, `7500` — нет.

## 4. Убавить TTL записи, заранее

За сутки до переезда поставьте TTL A-записи в 60 секунд. Это делается
**до** переключения, иначе роутеры будут приходить на старый адрес ещё
столько, сколько был старый TTL.

## 5. Переключить одно устройство и проверить

До переключения DNS возьмите **свой** тестовый роутер и направьте его
на новый адрес по IP — через SSH-туннель со страницы устройства. Он должен
появиться на дашборде новой машины. Это проверяет главное: что токен
и TLS совпали.

Не сошлось — правьте `frps.toml`, а DNS не трогайте. Пока переключено одно
устройство, цена ошибки — одно устройство.

## 6. Переключить DNS

Перевесьте A-запись на новую машину. Дальше:

* роутеры переподключаются сами, по мере того как разрешают имя заново —
  от минуты до нескольких часов;
* **старый frps держите включённым**: те, кто ещё не переехал, работают
  через него.

Наш visitor ходит по тому же имени и переедет вместе со всеми, но его
контейнер держит разрешённый адрес в соединении — перезапустите его,
чтобы не ждать:

```bash
cd /opt/router-shop && docker compose restart frpc worker
```

Если `FRP_DASHBOARD_URL` указывает на IP, а не на имя, — поправьте его
в `.env` до перезапуска, иначе статусы продолжат читаться со старой машины.

## 7. Дождаться, пока старый опустеет

Смотрите оба дашборда. Переезд закончен, когда на старом ноль, и ноль
держится несколько дней — роутер у клиента может быть выключен неделю
и прийти на старый адрес позже всех.

Пока не опустел, разница между дашбордами — это ровно те устройства,
которых наш visitor в эту минуту не видит: показания по ним не снимаются
и статус «на связи» у них неверный. Само по себе это не поломка и проходит
вместе с переездом.

## 8. Выключить старый

Только после этого:

```bash
cd /opt/frps && docker compose down
```

Машину не удаляйте ещё неделю: вернуть A-запись обратно — это минута,
а поднять всё заново — вечер.

## Что ломается, если сделать не в том порядке

| Ошибка | Чем оборачивается |
|---|---|
| выключили старый frps до переезда | роутеры, не успевшие переехать, недоступны совсем |
| токен на новой машине не тот | весь парк подключается и получает отказ |
| `transport.tls.force` не совпал с `FRP_TLS_ENABLED` | то же самое, и в логах только «connection closed» |
| не убавили TTL заранее | переезд растягивается на старый TTL |
| открыли `7500` наружу | список всего парка с именами прокси доступен любому |
| забыли перезапустить `frpc` | наш visitor остаётся на старом адресе и видит убывающую половину парка |
