# Перенос витрины на titanvps.pro

Задача: покупатель заходит на `titanvps.pro`, а имя
`vbotrouters.titanvps.click` и адрес сервера с приложением
(`82.197.73.251`) не видит никто.

Приложение никуда не переезжает. Переезжает только **адрес**: перед ним
встаёт отдельная ВМ, которая принимает клиентов и передаёт запросы внутрь.

```
клиент ──443──▶ ВМ-прокси ──────443──────▶ 82.197.73.251:8443
                titanvps.pro               приложение, порт закрыт
                                           файрволом на адрес ВМ
```

**Внимание: `titanvps.pro` сейчас занят.** Он резолвится на `5.34.214.243` —
тот самый хост с remnanode. Витрина на этом имени означает, что A-запись
apex переезжает на ВМ-прокси, и всё, что сегодня обращается к
`titanvps.pro`, поедет туда же. Reality ходит на ноду по подставному SNI
и на имя не смотрит, но перед переносом стоит убедиться, что на apex
не завязаны ссылки подписок и вход в панель. Если завязаны — либо сначала
перевести их на своё имя, либо взять для витрины поддомен.

**Прокси ставится на отдельную ВМ, не на ту, где remnanode.** Там 443
занят нодой, и её пришлось бы двигать, роняя клиентов. На своей ВМ порт
свободен, нода не трогается вообще. Конфиг с разделением по SNI
(`stream-sni.conf`) остаётся в репозитории на случай, если делить хост
всё-таки придётся, — сейчас он не нужен.

## Почему одного прокси мало

Спрятать origin — это три вещи сразу, и любой пропущенной хватает, чтобы
адрес всплыл:

1. **DNS.** Пока `vbotrouters.titanvps.click` резолвится, адрес берётся
   одной командой `dig`.
2. **Сертификат.** Публичное имя попадает в CT-логи — открытый журнал всех
   выписанных сертификатов, его просматривают поиском по домену. Поэтому
   origin переходит на самоподписанный: у него больше нет публичного имени,
   и выписывать ему нечего.
3. **Ссылки в самом приложении.** Фото каталога, баннер, картинки витрины,
   ссылка на инструкцию — всё это абсолютные адреса, собранные из
   `API_PUBLIC_BASE_URL`. Не поменять — и витрина покажет старое имя
   в адресе первой же картинки.

Плюс сеть: пока 8443 на origin открыт всем, прокси обходится сканированием
диапазона.

## Порядок

Шаги 1–3 ничего не ломают: старый адрес продолжает работать. Ломающий —
четвёртый, и до него витрина уже должна открываться по новому имени.

### 1. ВМ и DNS

На новой ВМ нужен только nginx. Записать её адрес:

```
titanvps.pro.  A  <IP ВМ-прокси>
```

`vbotrouters.titanvps.click` пока **не трогать** — на нём работает боевой
сервис, и он остаётся запасным путём до конца переезда.

### 2. Сертификат на прокси

```bash
apt update && apt install -y nginx certbot
```

```bash
certbot certonly --standalone -d titanvps.pro
```

`--standalone` сам поднимает временный сервер на 80. Если nginx уже
слушает 80 — сначала `systemctl stop nginx`.

### 3. Origin закрывается, прокси включается

Всё в этом шаге, кроме последней команды, можно делать не спеша: старый
адрес работает.

**На origin.** Самоподписанный сертификат — публичного имени у сервера
больше не будет, значит и в CT-логах его не будет:

```bash
mkdir -p /opt/router-shop/deploy/origin-tls && cd /opt/router-shop/deploy/origin-tls && openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -keyout origin.key -out origin.crt -subj "/CN=titanvps.pro" -addext "subjectAltName=DNS:titanvps.pro,DNS:cdn.titanvps.pro"
```

Ключ в репозиторий не попадает — каталог в `.gitignore`. Второе имя
в SAN стоит с запасом под списки и прошивки: перевыпускать сертификат
потом — это ещё и копировать его заново на прокси.

Приложение поднимается со своим nginx на 8443; 80 и 443 остаются чужому
Caddy, он на этом сервере не один:

```bash
cd /opt/router-shop && sed -i 's|^COMPOSE_FILE=.*|COMPOSE_FILE=docker-compose.yml:docker-compose.origin.yml|' .env && grep '^COMPOSE_FILE' .env
```

```bash
cd /opt/router-shop && git pull --ff-only && docker compose up -d --remove-orphans
```

Порт открывается только для прокси:

```bash
ufw allow from <IP ВМ-прокси> to any port 8443 proto tcp && ufw deny 8443/tcp
```

**На прокси.** `shop-site.conf` → `/etc/nginx/conf.d/`, в нём заменить
`ORIGIN_IP` на `82.197.73.251`. Сертификат origin (`origin.crt` с шага выше)
скопировать в `/etc/nginx/origin-ca.pem`:

```bash
sed -i 's/ORIGIN_IP/82.197.73.251/' /etc/nginx/conf.d/shop-site.conf && nginx -t && systemctl reload nginx
```

Проверить, что витрина открылась и что старого имени в ней нет:

```bash
curl -s https://titanvps.pro/ | grep -c "titanvps.click"
```

Ноль — чисто. Не ноль — значит остался шаг с `API_PUBLIC_BASE_URL` ниже.

**Последняя команда шага, на origin.** Переписать адрес, из которого
собираются ссылки:

```bash
cd /opt/router-shop && sed -i 's|^API_PUBLIC_BASE_URL=.*|API_PUBLIC_BASE_URL=https://titanvps.pro|' .env && make deploy
```

Бот и веб-админка ходили к API через публичный домен, то есть через чужой
Caddy. Оверлей публикует API на петле — перевести их туда:

```bash
systemctl cat router-bot | grep EnvironmentFile
```

```bash
sed -i 's|^FLEET_API_URL=.*|FLEET_API_URL=http://127.0.0.1:8000|' <файл окружения> && systemctl restart router-bot router-webadmin
```

### 4. Убрать старое имя

Только после того, как по новому адресу прошёл целиком заказ: каталог,
оплата, карточка заказа.

`vbotrouters.titanvps.click` удаляется из DNS, его блок — из Caddy на origin.

Имя останется в CT-логах навсегда: сертификат уже выписан, запись оттуда
не убирается. Но без DNS адрес по нему не берётся.

## Проверка, что спрятали

```bash
dig +short vbotrouters.titanvps.click
```

Пусто — записи нет.

```bash
curl -sk --max-time 5 https://82.197.73.251:8443/healthz || echo "порт закрыт"
```

```bash
curl -s https://titanvps.pro/ | grep -o "82\.197\.73\.251\|titanvps\.click" | sort -u
```

Пусто — ни адреса, ни старого имени в выдаче нет.

## Что осталось на потом

* **Списки и прошивки.** В этот заход не входят: роутеры тянут списки
  со старого `vm171085`, адрес манифеста в прошивку ещё не прописан.
  Но адрес им нужен **до выпуска партии** — зашитый в образ он меняется
  только перевыпуском. Заготовка под второе имя `cdn.titanvps.pro` —
  в комментариях конфигов, в SAN сертификата origin оно уже есть.
* **Вебхук Platega** — адрес колбэка в личном кабинете провайдера. Сейчас
  колбэк уходит на сторону другого бота, а статус мы узнаём опросом, так
  что переезд его не задевает; но если колбэк когда-нибудь переведут на нас,
  адрес должен быть новый.

## Откат

Убрать конфиг из `/etc/nginx/conf.d/` на прокси и вернуть на origin
`COMPOSE_FILE` без оверлея. Пока шаг 4 не сделан, старое имя работает,
и откат — это просто «перестать пользоваться новым».
