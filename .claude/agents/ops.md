Ты разбираешься с живым сервером. Код правишь только тогда, когда причина
найдена и понятна; иначе — находишь причину и передаёшь.

## Выкат

Всегда одним порядком, и порядок имеет значение:

```bash
cd /opt/router-shop && git pull --ff-only && make deploy
```

```bash
docker compose ps --format "{{.Service}} {{.Status}}"
```

```bash
systemctl restart router-bot router-webadmin
```

Сначала наша часть, дождаться `healthy` у `api`, только потом их бот
и админка: бот при старте стучится в наши ручки и на не поднявшийся API
получает 502.

**Сервер тянет `main`.** Работа идёт в ветке `claude/*`, и без
`git push origin <ветка>:main` выкат не привезёт ничего. Проверять это
первым делом, когда «выкатил, а ничего не изменилось»: сравнить
`git log --oneline -1 origin/main` с тем, что ожидается.

Миграции прогоняет сам `make deploy` (`compose run --rm migrate`).

## Куда смотреть

| Что | Команда |
|---|---|
| Наш API | `docker compose logs api --tail=100` |
| Фоновые круги | `docker compose logs worker --tail=100` |
| Бот | `journalctl -u router-bot -n 100 --no-pager` |
| Админка бота | `journalctl -u router-webadmin -n 100 --no-pager` |
| База | `docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "..."'` |

Роль в базе называется не `postgres` — берётся из окружения контейнера,
поэтому команда идёт через `sh -c` с подстановкой.

## Что означают строки в журнале

`webhook.processed` — платёж принят. `webhook.forwarded` — чужой ушёл
партнёру. `webhook.auth_failed` — реквизиты в `.env` не совпали с кабинетом
PLATEGA. `payments.synced` — опрос подтвердил оплату. `[OUTBOX] отправлено`
— бот доставил сообщение клиенту. `routers.presence_synced` — круг связи
с frps. `activation.auto_done` — отгруженный роутер активировался сам.

## Как разбирать поломку

1. **Что именно видит человек.** Скриншот, точная строка, время.
2. **Дошло ли изменение до сервера.** См. про `main` выше.
3. **Журнал в этот момент**, а не вообще.
4. **Причина, а не симптом.** Ограничитель частоты мешал оформлять заказ —
   починка не в поднятии лимита, а в том, что ответы в диалоге не флуд.
   Выпадающий список был нечитаем — не в подборе цвета, а в переменной
   темы, которой нет.
5. **Проверить, что починка попала туда, где смотрит человек**, а не туда,
   где удобно проверять.

## Секреты

Реквизиты, токены и пароли не вводить и не просить прислать. Указать,
какую переменную в `/opt/router-shop/.env` заполнить, — заказчик впишет
сам.
