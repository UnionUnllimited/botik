Ты работаешь с нашим бэкендом: FastAPI + async SQLAlchemy + APScheduler,
Postgres в docker. Начинай с `docs/state.md` — там картина и решения
заказчика с датами.

## Что здесь живёт

`core/` — модели, сервисы, тексты уведомлений, конфигурация.
`api/routes/catalog_api.py` — всё для бота и его админки: каталог, заказы,
оплата, «Мой роутер». `api/routes/fleet_api.py` — парк роутеров, туннели,
консоль, списки доменов. `worker/` — фоновые круги. `migrations/` — alembic.

## Правила, купленные дорого

**Деньги — `Numeric(12,2)`, никогда float.** Наружу отдаются строкой:
по дороге через JSON float теряет копейки.

**Время в базе UTC, клиенту показывается московское.** `core/dates.py`.

**Ленивая подгрузка в асинхронной сессии — это исключение, а не запрос.**
Всё, что читается у связанного объекта, грузится через `selectinload`.
Заказ передавать в функции только с загруженными `items` и `delivery`.

**Одна сессия — одна задача.** Нельзя трогать сессию из нескольких
одновременных корутин. Если нужен параллельный обход сети (опрос роутеров,
массовые действия), сеть идёт параллельно, а запись в базу — до и после,
последовательно. Пример: `_over_the_tunnel` в `fleet_api.py`.

**Отказ одного не отменяет остальных.** В любом обходе списка (роутеры,
платежи, подписки) ошибка ловится внутри итерации и превращается в строку
отчёта. Половина парка молчит всегда.

**Провайдер оплаты спрашивается перед тем, как что-то гасить.** Ссылка
PLATEGA живёт 15 минут, колбэк уходит другому боту, статус мы узнаём
опросом. Отменить платёж по своим часам, не спросив провайдера, — прямая
потеря денег: клиент заплатил на пятнадцатой минуте, мы отменили на
шестнадцатой.

**Второй платёж по заказу не должен идти общим путём.** Доставка
оплачивается отдельно (`PaymentPurpose.DELIVERY`). В `_apply_success`
её ветка стоит **до** поиска тарифа по составу заказа — иначе клиент
получит вторую подписку за оплату перевозки.

**Подписка привязана к устройству, а не к клиенту.** У владельца двух
роутеров две подписки. Всё, что двигает срок в панели, берёт
`subscription.device_id`, а не «последний активированный роутер».
На этом уже обожглись дважды.

**Ноль — законная величина, «не задано» — отдельная отметка.** Цена
доставки ноль означает «бесплатно»; «ещё не считали» отличается полем
`quoted_at`. Тот же принцип везде, где ноль может быть настоящим ответом.

## Миграции

Пишутся руками, номер по порядку (`0013_...`). В `upgrade()` не только
схема, но и данные: если новое поле меняет смысл старых строк, их надо
привести. Пример: `0013` помечает уже оплаченные доставки, чтобы с них
не потребовали денег второй раз.

`downgrade()` пишется всегда, даже если им никто не воспользуется: он
заставляет подумать, что именно теряется.

## Проверки

```
python -m pytest -q
ruff check .
```

Тесты по возможности проверяют **свойство**, а не строку кода. Если
свойство иначе не поймать (порядок веток, наличие проверки), проверка по
исходнику допустима — но с внятным сообщением об ошибке, объясняющим,
чем это грозит.

База в тестах недоступна: всё, что требует Postgres, проверяется на
чистых функциях или по исходнику.
