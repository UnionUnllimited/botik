# Агенты проекта

Разделение по швам, которые в этом проекте настоящие, а не по ролям из книжки.
Границы проходят там, где разные правила игры: свой код против чужого, код
против текстов, разработка против живого сервера.

| Агент | Чем занимается | Где работает |
|---|---|---|
| `backend` | Наша часть: расчёты, заказы, подписки, активация, миграции | `core/`, `api/`, `worker/`, `migrations/` |
| `bot` | Чужой продукт: экраны бота и его админка | `bot/` |
| `texts` | Всё, что читает клиент: тексты, кнопки, уведомления | `bot/src/shop_texts.py`, `core/texts.py`, `bot/button_registry.py` |
| `review` | Проверка свежих изменений до выката | весь репозиторий, только чтение |
| `ops` | Выкат и разбор живых поломок по журналам | сервер, скриншоты, логи |

## Общее для всех

**Запрещённое слово из трёх букв не используется нигде** — ни в текстах,
ни в коде, ни в именах полей, ни в коммитах. Формулировка продукта:
«роутер с подпиской на сервис стабильного доступа к зарубежным ресурсам».

**Начинать с `docs/state.md`.** Там вся картина и все решения заказчика
с датами. Там же в конце список «Осталось».

**Перед коммитом:**

```
python -m pytest -q
ruff check .
```

`ruff` запускать без трубы: `| tail -1` съедает код возврата, и упавшая
проверка выглядит пройденной. Так один коммит уже ушёл с ошибками.

**Ветка не равна выкату.** Сервер тянет `main`. Работа идёт в `claude/*`,
и без `git push origin <ветка>:main` выкат не привезёт ничего. Это уже
случалось: заказчик выкатил, ничего не изменилось, разобрались по скриншоту.

**Два процесса, две базы.** Наш API с Postgres в docker и чужой бот
с SQLite на хосте не видят баз друг друга. Общение только по HTTP через
`/api/v1/catalog/*` и `/api/v1/fleet/*`.
