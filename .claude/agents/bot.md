Ты работаешь в `bot/` — это **чужой продукт** (RM-Only), взятый за основу
решением заказчика. Наш код в нём — острова: `bot/src/*` и наши страницы
в `bot/web_admin/`. Начинай с `docs/state.md`, раздел «Смена основы».

## Устройство

Два процесса на хосте, вне docker, со своим venv: бот (aiogram, polling)
и админка (Quart + Jinja2). База — SQLite рядом. До нашего Postgres они
не дотягиваются: всё через HTTP в `bot/src/shop_api.py`.

Импорты в чужом коде **плоские**: `from app_config import app_conf`,
а не `from bot.app_config import ...`. Наш код в `bot/src/` следует тому же.

## Правила, купленные дорого

**Декоратор маршрута приклеивается к следующей функции.** Вставив хелпер
между `@admin_bp_instance.route(...)` и её `async def`, вы приклеиваете
маршрут не туда — и `url_for` роняет `base.html`, а с ним **всю админку**,
а не одну страницу. Ровно это уже случилось.
Сторож: `tests/test_bot_admin_routes.py`.

**Текст из базы может быть пустым.** `app_conf.get(key)` вернёт `None`,
если ключ не заведён, а дальше `.format()` или склейка со строкой — и бот
молча перестаёт отвечать: исключение съедает глобальный обработчик.
Каждый новый текст надо и завести в `bot/src/shop_texts.py`, и читать
с запасным значением. На этом бот однажды перестал отвечать на `/start`.

**Фигурных скобок в текстах не бывает, кроме подстановок.** Тексты уходят
в `.format()`; лишняя скобка роняет экран.

**Кнопки заводятся в реестре.** `bot/button_registry.py` — иначе клиент
увидит имя ключа вместо подписи. Подпись правится в админке, поэтому
в коде она только значение по умолчанию.

**Ссылки в сообщениях живут дольше сообщений.** Платёжная ссылка PLATEGA
живёт 15 минут: класть её в напоминание бессмысленно. Живая ссылка
выдаётся по нажатию кнопки, когда клиент готов.

**Ответ в диалоге — не флуд.** Ограничитель частоты пропускает сообщения,
когда у пользователя есть состояние FSM. Оформление заказа это пять
сообщений подряд, и на общем лимите оно упиралось в «слишком много».

## Админка

Страницы наследуют `base.html`. Данные приходят из нашего API — шаблон
рисует то, что дали, и ничего не досчитывает.

**Новая страница добавляется в `tests/test_bot_admin_templates.py`.**
Там она рисуется на выдуманных данных со `StrictUndefined`: обращение
к непереданной переменной падает в тесте, а не пятисоткой у оператора.
Список `OURS` — наши страницы, они рисуются строго.

**Фильтры перечисляются в одном месте.** Забытый в ссылке пагинации
фильтр молча сбрасывается на второй странице, и оператор видит не свой
отбор. Пример: `FLEET_FILTER_KEYS` в `routers_fleet.py`.

**Выпадающие списки на тёмной теме.** Цвета пунктов заданы в `base.html`
через переменные темы. Ссылка на несуществующую переменную даёт белым
по белому — так и было с `--admin-card`, которой в теме нет.

## Проверки

```
python -m pytest -q
ruff check .
python -m compileall -q bot/src
```

Импортировать `bot/main.py` в тестах нельзя — он тянет половину бота
и требует его окружения. Проверки по нему делаются чтением исходника
(см. `tests/test_bot_main_menu_texts.py`).
